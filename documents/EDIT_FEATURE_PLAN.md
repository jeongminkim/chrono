## 1. 요구사항 요약

### 편집 기능

- LNB 태그 클라우드 아래에 **편집 허용 스위치**를 둔다. 기본값은 off이며, on일 때만 아래 기능을 쓸 수 있다.
- **테마 삭제:** LNB 각 테마 오른쪽의 휴지통 아이콘. 확인 창을 거친 뒤 해당 테마의 DB 데이터와 첨부 이미지를 삭제한다.
- **사건 삭제:** 타임라인 카드 오른쪽 위의 휴지통 아이콘. 확인 창을 거친 뒤 해당 사건의 DB 데이터와 첨부 이미지를 삭제하고 화면을 새로 고친다.
- **상세 패널 편집**
  - 연도·날짜 표시를 변경 폼으로 바꾼다.
  - 이미지 영역 아래의 `+` 버튼으로 이미지를 추가한다(최대 5개).
  - 제목 오른쪽 편집 아이콘을 누르면 `input[type=text]`로 바뀌고, Enter를 누르면 저장한다.
  - 내용 오른쪽 편집 아이콘을 누르면 `textarea`로 바뀌고, 아래 확인 버튼을 누르면 저장한다.
  - 각 태그 오른쪽 `x` 버튼으로 즉시 삭제하고, 아래 입력창에 쉼표로 구분한 단어를 넣고 Enter를 누르면 추가한다.
- 모든 변경은 저장 즉시 LNB(테마 개수, 태그 클라우드)와 타임라인에 반영된다.

### import 보완

- `data.json`에 DB에 이미 있는 `theme.id`의 데이터가 들어 있으면, 기존 데이터에 **추가(append)** 한다.

## 2. 먼저 짚어야 할 이슈

구현 방향을 정하는 이슈다. 각 항목에 권장안을 적었고, 별도 지시가 없으면 권장안으로 진행한다.

### 이슈 1 (높음) — 인증은 Nginx가 맡는다 (확정)

편집 스위치는 화면에서 버튼을 숨기고 보이는 역할만 하며 보안 장치가 아니다. **인증은 Nginx에서 처리해, 인증된 사용자만 `/chrono/` 전체에 접근하게 한다(2026-09-29 확정).** 앱은 자체 인증을 두지 않고, Nginx를 통과한 요청을 신뢰한다.

이 방식에서 남는 위험과 앱 쪽 최소 대응은 다음과 같다.

- **Nginx 우회:** `chrono:3000`은 호스트 포트를 공개하지 않지만, 같은 Docker 네트워크(`proxy`)의 다른 컨테이너는 Nginx를 거치지 않고 직접 접근할 수 있다. 그 네트워크에 신뢰하는 컨테이너만 두는 것을 운영 전제로 README에 명시한다.
- **CSRF:** Basic Auth나 세션 쿠키처럼 브라우저가 인증 정보를 자동으로 보내는 방식이면, 인증된 사용자가 다른 사이트를 열었을 때 그 사이트가 쓰기 요청을 보낼 수 있다. 앱은 다음 두 가지를 검사해 막는다.
  - 모든 쓰기 요청에 사용자 정의 헤더 `X-Chrono-Edit: 1`을 요구한다. 폼이나 단순 요청으로는 이 헤더를 붙일 수 없다.
  - `Sec-Fetch-Site` 헤더가 있는데 `same-origin`이 아니면 거부한다.
- **Nginx 설정:** 인증 설정(`auth_basic` 또는 `auth_request` 등)은 운영 Nginx에서 관리하고, `nginx/chrono-proxy.conf.example`에는 인증 설정이 필요하다는 주석과 Basic Auth 예시만 둔다.

### 이슈 2 (높음) — 사건 하나에 미디어가 하나뿐인 현재 규격

지금 `media`는 객체 하나(이미지 또는 동영상)다. 이미지를 최대 5개까지 붙이려면 `data.json` 규격을 바꿔야 한다. 새 규격은 **2.1절**에 정리했다.

- 카드에는 첫 번째 미디어를, 상세 패널에는 모두를 세로로 나열해 보여준다.
- DB의 `items.media` 컬럼은 JSON 배열을 저장한다. 기존 객체 값은 스키마 버전 2 마이그레이션에서 `[객체]`로 바꾼다.
- **파생 이슈:** 추가한 이미지를 지우는 기능은 요구사항에 없다. 잘못 올린 이미지를 없앨 방법이 없으므로, 편집 모드에서 각 이미지에 `x` 버튼을 함께 제공하기를 권장한다(태그 삭제와 같은 방식).

### 2.1 `data.json` 규격 변경 — `media` 배열

`version`은 1로 유지한다. 기존 파일(객체 하나)도 그대로 import할 수 있어야 하므로, 버전을 올려 기존 파일을 거부할 이유가 없다.

| 항목 | 현재 | 변경 후 |
|---|---|---|
| `item.media` 형식 | 객체 하나 | **객체 배열** (1~5개). 객체 하나도 계속 허용하며, 읽을 때 `[객체]`로 바꾼다 |
| 개수 | 0~1 | 0~5. 이미지와 동영상을 섞어서 5개까지. 빈 배열은 필드 생략과 같다 |
| 순서 | — | 배열 순서대로 표시. 첫 번째가 카드 대표 이미지 |
| 각 객체의 필드 | `type`, `src`, `alt`, `caption`, `poster` | 변경 없음 (이미지: `src`·`alt` 필수, 동영상: `src` 필수) |
| 로컬 경로·https 규칙 | `data.json` 기준 상대 경로, 폴더 밖 금지 | 변경 없음. 배열의 모든 항목에 적용 |
| 중복 | — | 같은 `src`가 한 사건에 두 번 나오면 오류 |
| export 출력 | 객체 하나 | 항상 배열 |

변경 후 예시:

```json
{
  "id": "2024-05-japan-osaka",
  "date": "2024-05-23",
  "title": "일본 오사카",
  "description": "3인 가족이 USJ와 간사이 와이드 패스로 돌아본 오사카.",
  "tags": ["해외", "일본", "오사카"],
  "media": [
    { "type": "image", "src": "images/osaka-usj.jpg", "alt": "USJ 입구의 지구본 조형물", "caption": "USJ 입구" },
    { "type": "image", "src": "images/osaka-dotonbori.jpg", "alt": "도톤보리 강가의 네온 간판" },
    { "type": "video", "src": "https://youtu.be/FlpstXNjImY", "caption": "마리오 카트 탑승" }
  ]
}
```

기존 형식(계속 허용):

```json
"media": { "type": "image", "src": "images/osaka-usj.jpg", "alt": "USJ 입구의 지구본 조형물" }
```

오류 메시지(`parseTimelineData`에 추가):

- `…media는 객체 또는 최대 5개의 객체 배열이어야 합니다.`
- `…media[2].src가 같은 사건에서 중복됩니다.`
- 개별 항목 오류는 `…media[1].alt은(는) …`처럼 배열 위치를 포함한다.

함께 바꿀 것:

- `src/data.ts`: `TimelineItem.media` 타입을 `TimelineMedia[]`로 바꾼다. 파싱 결과는 항상 배열이고, 없으면 필드를 생략한다.
- `store.mjs`: import 시 배열의 모든 로컬 파일을 검증·복사한다. `removeUnusedMedia`와 export도 배열 전체를 순회한다.
- `import/HOWTO_MAKE_DATA.md`: 미디어 절, 예시, LLM 프롬프트(`media`는 최대 5개 배열)를 수정한다.
- 테스트: 객체와 배열 입력이 같은 결과가 되는지, 6개 거부, 중복 `src` 거부, 배열 중간 항목 오류 위치 표시를 확인한다.

### 이슈 3 (높음) — 이미지 업로드 크기와 Nginx 제한

Nginx의 `client_max_body_size` 기본값은 1MB다. 휴대폰 사진은 대부분 이보다 크므로 업로드가 413 오류로 실패한다.

- **권장안:** `nginx/chrono-proxy.conf.example`의 `location /chrono/`에 `client_max_body_size 10m;`을 추가하고, README의 Nginx 연동 절차에 reload가 한 번 더 필요하다고 적는다. 앱 서버도 요청 본문을 10MB로 제한한다(import 제한과 동일).

### 이슈 4 (중간) — 업로드 이미지의 대체 텍스트

규격상 이미지에는 `alt`가 필수다. 업로드 UI에 `alt` 입력이 없다.

- **권장안:** 업로드할 때 `alt`를 비워 두면 서버가 `"<사건 제목> 사진 <n>"`을 기본값으로 넣는다. `alt`와 `caption` 편집은 이번 범위에서 빼고, 필요하면 다음에 추가한다.

### 이슈 5 (중간) — "내용"이 가리키는 필드

상세 패널은 `body ?? description`을 보여주고, 카드는 `description`(요약)을 보여준다. "내용" 편집이 어느 필드를 바꾸는지 정해야 한다.

- **권장안:** 상세 패널의 "내용" 편집은 `body`를 수정한다. `body`가 없는 사건이라면 편집기의 초기값을 `description`으로 채우고, 저장하면 `body`가 새로 생긴다. 카드 요약(`description`) 편집은 범위에서 뺀다.

### 이슈 6 (중간) — 날짜 폼과 연도만 있는 날짜

`date`는 `YYYY` 또는 `YYYY-MM-DD` 형식이다. `<input type="date">` 하나로는 연도만 있는 날짜를 표현할 수 없다.

- **권장안:** 연도 `<input type="number">`와 월·일 `<select>` 두 개(맨 앞에 "선택 안 함")로 구성한다.
  - 월과 일을 모두 고르면 `YYYY-MM-DD`, 둘 다 비우면 `YYYY`로 저장한다. 하나만 고른 상태는 저장하지 않고 안내를 보여준다.
  - 값이 바뀔 때(`change`) 바로 저장한다. 서버는 `isValidDate`로 한 번 더 검증한다.
  - 날짜가 바뀌면 타임라인 정렬도 바뀐다. 선택 중인 카드는 유지하고, 필요하면 그 위치로 스크롤한다.

### 이슈 7 (중간) — import의 "append"는 이미 대부분 동작한다

현재 `importDir`는 테마 id가 같으면 테마 이름을 덮어쓰고, 항목은 `(theme_id, id)` 기준 upsert를 한다. 따라서 **기존 테마에 새 id의 항목을 넣으면 이미 추가되고 있다.** 요구사항과 어긋나는 부분은 다음 두 가지다.

1. **같은 id 항목을 덮어쓴다.** 편집 기능이 생기면 화면에서 고친 내용이, 예전 `data.json`을 다시 import할 때 조용히 사라진다.
2. **테마 이름을 덮어쓴다.**

- **권장안:** import의 기본 동작을 **추가 전용**으로 바꾼다.
  - 새 테마와 새 항목만 추가한다. 이미 있는 항목은 건너뛰고 결과에 `skipped` 개수와 id 목록을 출력한다. 기존 테마 이름은 유지한다.
  - 덮어쓰기가 필요할 때를 위해 `--overwrite` 옵션을 두어 지금의 upsert 동작을 유지한다. `--replace`(파일에 없는 항목 삭제)는 `--overwrite`를 포함하는 것으로 정리한다.
  - export → 수정 → import로 데이터를 고치는 절차는 `--overwrite`를 쓰도록 README와 HOWTO를 수정한다.

### 이슈 8 (낮음) — 이미지 파일 공유와 삭제

미디어 파일은 내용 해시로 저장되어, 같은 이미지를 여러 사건이 공유할 수 있다. 테마나 사건을 지울 때 그 파일을 바로 지우면 다른 사건의 이미지가 깨진다.

- **권장안:** 삭제 API는 DB 행만 지우고, 파일은 기존 `removeUnusedMedia()`로 **어디서도 참조하지 않는 파일만** 정리한다. 업로드, 이미지 삭제, 사건·테마 삭제 모두 같은 함수를 쓴다.

### 이슈 9 (낮음) — 동시 편집과 자동 갱신

화면은 5초마다 `/api/timeline`을 다시 받는다. 편집 중에 데이터가 새로 들어오면 입력 중인 값이 덮일 수 있고, 두 탭에서 동시에 고치면 나중에 저장한 쪽이 이긴다.

- **권장안:**
  - 편집 입력창이 열려 있는 동안에는 받은 데이터를 그 필드에 반영하지 않는다(입력 중인 로컬 값을 우선).
  - 동시 편집은 개인용 서비스 특성상 "마지막 저장 우선"으로 두고, 충돌 감지(`If-Match: rev`)는 필요해질 때 추가한다.

### 이슈 10 (낮음) — 모바일에서 편집 불가

760px 이하에서는 LNB가 숨겨져 편집 스위치와 테마 삭제에 접근할 수 없다.

- **권장안:** 이번 범위에서는 데스크톱 전용으로 둔다. 모바일 편집이 필요하면 상세 패널 위쪽에 스위치를 한 번 더 두는 방식으로 확장한다.

### 이슈 11 (낮음) — 확인 창과 "새로고침"

- "alert로 물어본다"는 확인/취소가 필요하므로 `window.confirm()`을 쓴다. 문구에 대상 이름을 넣는다. 예: `"우주 탐사의 역사" 테마와 사건 12개를 삭제할까요? 되돌릴 수 없습니다.`
- 사건 삭제 후의 "새로고침"은 페이지를 다시 불러오는 것이 아니라 **데이터를 다시 받아 화면을 갱신하는 것**으로 구현한다. 필터와 스크롤 위치를 유지하기 위해서다.
- 지금 선택된 테마나 열린 사건을 삭제하면 테마는 "전체"로, 상세 패널은 닫힘으로 바꾼다.

## 3. API 설계

인증은 Nginx가 처리한다(이슈 1). 앱은 모든 쓰기 요청에 `X-Chrono-Edit: 1` 헤더를 요구하고, `Sec-Fetch-Site`가 `same-origin`이 아니면 403으로 거부한다(CSRF 방지). 성공하면 `revision`을 1 올리고 `{ revision }`을 응답한다. 클라이언트는 응답을 받으면 바로 `/api/timeline`을 다시 요청해 화면 전체를 갱신한다.

| 메서드·경로 | 본문 | 동작 |
|---|---|---|
| `DELETE /chrono/api/themes/:themeId` | 없음 | 테마와 소속 사건 삭제(FK cascade), 참조 없는 미디어 정리 |
| `DELETE /chrono/api/themes/:themeId/items/:itemId` | 없음 | 사건 삭제, 참조 없는 미디어 정리 |
| `PATCH /chrono/api/themes/:themeId/items/:itemId` | JSON `{ date?, title?, body?, tags? }` | 부분 수정. 수정된 사건 전체를 기존 `parseTimelineData` 규칙으로 다시 검증 |
| `POST /chrono/api/themes/:themeId/items/:itemId/media` | 이미지 바이너리(`Content-Type: image/*`), 쿼리 `alt?` | 미디어 배열 끝에 추가. 5개를 넘으면 409 |
| `DELETE /chrono/api/themes/:themeId/items/:itemId/media/:index` | 없음 | 미디어 삭제(이슈 2의 권장 추가 기능) |

- **업로드 방식:** multipart 파서를 넣지 않고, 이미지 바이트를 본문 그대로 받는다. 의존성이 추가되지 않는다.
  - 형식은 `Content-Type`과 파일 앞부분의 시그니처(magic bytes)로 함께 확인한다. 허용 형식은 import와 같다.
  - 저장은 import와 같은 `media/<sha256>.<ext>` 방식을 쓴다.
- **검증 재사용:** 수정한 사건을 `{ version: 1, themes: [{ id, name, items: [item] }] }` 형태로 감싸 `parseTimelineData`에 넣는다. 규격을 한 곳(`src/data.ts`)에서만 관리하기 위해서다.
- **태그:** 서버는 앞뒤 공백 제거, 빈 값 제거, 중복 제거를 한다. 클라이언트는 쉼표로 나눈 값을 기존 태그에 합쳐 `tags` 전체를 보낸다.
- **서버 라우팅:** 지금은 GET/HEAD만 허용한다. `/chrono/api/` 아래에서만 DELETE, PATCH, POST를 허용하고, 요청 본문은 JSON 64KB, 이미지 10MB로 제한한다.

## 4. 화면 설계

| 위치 | 편집 off (현재) | 편집 on |
|---|---|---|
| LNB 태그 클라우드 아래 | 스위치(off) | 스위치(on). 추가 인증 없이 바로 켜짐 |
| LNB 테마 행 | 이름 + 개수 | 개수 오른쪽에 휴지통 아이콘. "전체" 행에는 없음 |
| 타임라인 카드 | 그대로 | 오른쪽 위에 휴지통 아이콘. 누를 때 카드 선택(패널 열기)이 같이 일어나지 않게 이벤트 전파 차단 |
| 상세 패널 날짜 | `1957년 10월 4일` | 연도 입력 + 월·일 선택 |
| 상세 패널 미디어 | 첫 번째 미디어 | 모든 미디어 + 각 이미지 `x` + 아래 `+` 버튼(5개가 되면 숨김) |
| 상세 패널 제목 | 텍스트 | 오른쪽 편집 아이콘 → input, Enter 저장 / Esc 취소 |
| 상세 패널 내용 | 텍스트 | 오른쪽 편집 아이콘 → textarea + 확인·취소 버튼 |
| 상세 패널 태그 | 태그 목록 | 각 태그 `x`, 아래 쉼표 구분 입력창(Enter로 추가) |

- **스위치 상태:** 요구사항대로 기본 off이며 저장하지 않는다. 새로고침하면 다시 off가 된다.
- **Esc 키 충돌:** 지금 Esc는 상세 패널을 닫는다. 편집 입력창이 열려 있을 때는 Esc가 편집 취소에만 쓰이도록 패널 닫기보다 우선 처리한다.
- **디자인 시스템:** `src/ds/components.js`에 번들의 `Switch`를 추가로 export한다. 아이콘은 기존과 같은 lucide 아이콘인 `trash-2`, `pencil`, `plus`를 `public/icons/`에 추가한다. 버튼 모양과 색은 기존 `IconButton`, `Button`, `Tag` 토큰을 그대로 쓴다.
- **저장 중 표시:** 저장 중에는 해당 컨트롤을 비활성화한다. 실패하면 변경 전 값으로 되돌리고, 기존 `.notice` 영역에 오류를 보여준다.

## 6. 개발 단계

### 1단계 — 규격과 저장소

- 미디어 배열 규격, 스키마 v2 마이그레이션, 저장소 쓰기 함수
- import 추가 전용 기본 동작과 `--overwrite`

완료 조건: 기존 DB가 v2로 올라가도 화면이 그대로 보이고, 같은 `data.json`을 두 번 import하면 두 번째는 모두 `skipped`로 나온다.

### 2단계 — 쓰기 API

- 3장의 라우트, CSRF 방지 헤더 확인, 본문 제한, 업로드 검증

완료 조건: `X-Chrono-Edit` 헤더가 없거나 다른 출처에서 온 쓰기 요청은 거부되고, 테스트가 모든 거부 경로를 확인한다.

### 3단계 — 편집 스위치와 삭제

- 스위치, 테마·사건 삭제, 삭제 후 선택 상태 정리

완료 조건: 삭제 즉시 LNB 개수, 태그 클라우드, 타임라인이 갱신되고, 다른 사건이 같이 쓰던 이미지는 남아 있다.

### 4단계 — 상세 패널 편집

- 날짜 폼, 제목·내용 편집, 태그 추가·삭제, 이미지 추가·삭제, 여러 미디어 표시

완료 조건: 모든 편집이 저장 즉시 카드와 LNB에 반영되고, 5초 자동 갱신이 입력 중인 값을 덮지 않는다.

### 5단계 — 운영 반영과 문서

- Nginx 설정 예시, README, HOWTO 수정, 브라우저 확인(다크 모드 포함)

완료 조건: 인증된 Nginx를 통해 5MB 이미지를 업로드할 수 있고, 인증하지 않은 요청은 Nginx에서 차단된다.

## 7. 결정이 필요한 사항

아래는 권장안을 기본값으로 진행한다. 다르게 원하면 착수 전에 알려준다.

1. ~~쓰기 보호 방식~~ → **확정:** Nginx 인증 + 앱의 CSRF 방지 헤더 확인 (이슈 1)
2. ~~미디어 규격~~ → **확정:** `media` 배열, 동영상 포함 최대 5개, 객체 하나도 계속 허용 (2.1절)
3. 이미지 삭제 `x` 버튼 추가 (이슈 2, 요구사항 외 추가)
4. "내용" 편집 대상: `body` (이슈 5)
5. import 기본 동작: 추가 전용, 덮어쓰기는 `--overwrite` (이슈 7)
6. 모바일 편집: 이번 범위 제외 (이슈 10)

## 8. 구현 결과와 계획 대비 변경점

- **빈 테마 자동 삭제:** 사건 삭제로 테마에 사건이 하나도 남지 않으면 테마도 함께 삭제한다. 빈 테마는 규격상 표시할 수 없어 DB에 남겨 둘 이유가 없다.
- **미디어 정리 유예:** 참조하지 않는 미디어 파일은 만든 지 10분이 지난 것만 지운다(`openStore`의 `mediaGraceMs`). 서버의 편집 정리 작업이, import CLI가 복사만 하고 아직 커밋하지 않은 파일을 지우는 경쟁 상태를 막기 위해서다. 지운 이미지 파일은 최대 10분 동안 디스크에 남을 수 있다.
- **편집 모드의 상세 패널 태그:** 태그를 눌러 필터링하는 동작은 끄고 `x` 삭제만 동작한다. 삭제하려다 실수로 패널이 닫히는 것을 막는다.
- **내용을 모두 지우고 저장:** `body`를 삭제해 요약(`description`)이 대신 보이게 한다.
- **한글 입력:** 제목·태그·연도 입력의 Enter는 한글 조합 중일 때 무시해 두 번 저장되지 않게 했다.
- **확인 창:** 테마·사건·이미지 삭제 모두 `window.confirm()`을 쓴다.
- **검증:** `npm test` 11개(규격, 저장소, 서버 쓰기 API의 거부 경로 포함), 실제 데이터 사본에서 v1 → v2 마이그레이션과 브라우저의 편집·삭제 전 과정을 확인했다. 컨테이너 빌드와 Nginx 연동(업로드 크기 제한, 인증)은 이 환경에 Docker가 없어 검증하지 못했다.
